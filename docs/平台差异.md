# 平台差异 · 文件地图

> **一句话**：本项目是**单仓 + 共享内核 + 薄平台适配层**。九成代码 macOS / Windows 共用，
> 跟操作系统绑死的只有「启动器、安装器、开机自启、串口枚举」这一小圈。
> 所以**没有平台分支、没有分目录**——差异靠文件名后缀和 `lib/host.py` 一个总闸隔离。

---

## 0. 先分清两个「平台」

⚠️ 本项目里「平台」一词有**两个含义**，看文档和代码时别混：

| 说法 | 指的是 | 出现在哪 |
|---|---|---|
| **操作系统平台** | macOS / Windows | `lib/host.py` 的 `IS_WIN` / `IS_MAC` |
| **设备厂商平台** | 华为 VRP / H3C / 锐捷 / Cisco | `lib/platforms.py` 里的厂商档案 |

`lib/platforms.py` 文件名里的 "platforms" 指的是**设备厂商**（命令表 + 解析正则），
跟操作系统无关，它是**共享代码**。本文以下说「平台」一律指**操作系统**。

---

## 1. 总体结构

```
netdev/
├── netdev, netdev_cli.py, netdev_mcp.py   # 入口：netdev 是 Mac 脚本，.py 共享
├── lib/                                   # 共享内核（★ 平台判断只准写在 lib/host.py）
├── ui/                                    # 共享网页界面（混入 Mac 的 .command / start.sh）
├── tools/                                 # 共享桥接脚本（内含 if host.IS_WIN: 分支）
├── tests/                                 # 共享回归（CI 在 macOS 上跑）
├── config/                                # 共享配置模板 + 本机真身（真身不入仓）
├── docs/                                  # 共享文档
├── bin/                                   # ← macOS 专属启动器（.command / 无后缀脚本）
└── dist/
    ├── *.sh                               # ← macOS 打包
    └── installer/                         # ← 双平台安装器（.sh / .ps1 / .cs 分列）
```

## 3. 平台分支是怎么工作的

- **唯一总闸**：`lib/host.py`
  ```python
  IS_WIN  = sys.platform == "win32"
  IS_MAC  = sys.platform == "darwin"
  IS_POSIX = os.name == "posix"
  ```
- 别处**不要再写** `sys.platform == "win32"`。要判断平台就：
  ```python
  from lib import host
  if host.IS_WIN: ...
  ```
- 垫片顺带把三个 POSIX-only 的东西做了跨平台对应，别再各写一遍：
  `venv_python()`（venv 解释器路径）、`pid_alive()`（进程探活，替代 `os.kill(pid,0)`）、
  `serial_ports()`（串口枚举，替代写死 `/dev/cu.*`）。
- 桥脚本（`serial_bridge` / `ssh_bridge` / `telnet_bridge`）是**同一个文件两端跑**，
  内部用 `if host.IS_WIN:` 分叉，不是两份代码。

## 4. 新增「平台相关文件」时的规矩

1. **能共享就共享**，不要复制第二份（复制必然漂移）。
2. 确实要分平台 → **文件名带平台后缀**：
   - macOS：`.command`（可双击）/ `.sh`（命令行）
   - Windows：`.ps1`（脚本）/ `.cmd`（双击入口）
3. 判断平台**一律走 `host.IS_WIN`**，不要在业务代码里裸写 `sys.platform`。
4. 新加的 macOS 脚本**必须可执行**——见第 5 节。
5. 安装器新增文件时，记得同步 `dist/build_bundle.ps1` 的资产列表和安装脚本。

## 5. 两个跨平台坑（及现有防线）

| 坑 | 症状 | 防线 |
|---|---|---|
| **可执行位丢失** | Windows 提交会把 `100755` 抹成 `100644`（Windows 文件系统不记录权限位），Mac 上 `./netdev` 直接 `permission denied`、`.command` 双击打不开 | `.gitattributes` **管不了**权限位；靠 CI 闸门（`ci.yml` 新增步骤）+ `推送到GitHub.ps1` 自动兜底 |
| **换行符** | CRLF 会让 Mac 的 shell 脚本报 `bad interpreter` | `.gitattributes`：仓库内一律 LF，`.cmd/.bat` 保持 CRLF |

> 这两个坑 2026-10-07 都真实踩过一次：Windows 交接包同步上来时，
> 22 个文件的可执行位被抹掉，导致 macOS CI 变红（`netdev-mcp 启动包装脚本存在且可执行` 断言失败）。
> 修复见提交 `32e832c`。

## 6. 一分钟判断口诀

| 你改的东西 | 影响范围 |
|---|---|
| `lib/` `ui/` `tools/` `tests/` `netdev_cli.py` `netdev_mcp.py` `config/` | **两端都影响** |
| `lib/host.py` | **两端都影响** —— 这是平台分叉的唯一总闸，改它要格外小心 |
| `bin/*.command`、`netdev`、`netdev-mcp`、`ui/*.command`、`ui/start.sh`、`dist/**/*.sh` | **只影响 Mac** |
| `*.ps1`、`*.cmd`、`*.cs`、`requirements-win.txt` | **只影响 Windows** |
| `docs/`、`*.md`、`LICENSE`、`.github/` | 文档 / 协作，不影响运行 |
